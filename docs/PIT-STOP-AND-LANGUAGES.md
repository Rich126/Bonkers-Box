# Pit Stop Sprint and site languages

The default board is now **Checked runs** (`pitstop-v3`), with a fresh shuffled wheel order, server-side replay checks and a nice-try GIF screen for detected scripted inputs. See [Checked runs and nice-try screen](PIT-STOP-CHECKED-RUNS.md) for current protections and their limits. The earlier v1/v2 records remain archived and accessible.

Mario mode now uses `spencer_site_language_v2` (`en` by default; `es` only after explicit selection). The old front-page-only preference is ignored during this upgrade. The selected language persists and is shared with same-origin game frames and standalone game pages. Turning Mario mode off restores English. Mario mode also applies a Spanish-flag backdrop, a slim flag frame and a visible flag marker in every standalone game and embedded frame; full-screen canvases retain their playing surface inside that frame.

Every public game page loads the bundled Spanish catalogue and the shared language adapter. Instructions, question/answer copy, creative prompts, game feedback, dialogs, accessible labels and canvas text use that adapter. The Spanish word-guessing game selects Spanish words and includes Ñ in its keyboard. Rendering translations preserve option values, event handlers, game identifiers, player-entered names and stored scores. Game names and livery artwork remain recognisable. There are no runtime calls to a translation service. New English copy should receive a corresponding entry or parameterised pattern in `language-es.js`.

Pit Stop Sprint is available from the Local games menu and at `pit-stop/`. The full-stop sequence is: car arrives, hold the jack to raise it, service every tyre in the highlighted order, hold the jack to lower it, then wait for the crew-clear signal and release on green. Each tyre has four distinct actions: hold to loosen, tap to remove, tap to fit, hold to tighten. Only the current wheel is enabled. Releasing a hold early cancels its progress. On a keyboard, hold J for the jack and 1–4 for the wheels; Space releases the car.

Timing begins when the arriving car stops. Two 600 ms jack actions, eight 450 ms nut actions and a 300 ms crew-clear interval give a **5.100-second theoretical optimum**. Reactions and taps add time. Results show the gap from that optimum using the penalty-inclusive total. Early work and unsafe release presses add three seconds each and never skip required steps. Leaving the tab or window cancels a live attempt.

The leaderboard format selector retains **Earlier full stops** (`pitstop-v2`) and **Original tyre challenge** (`pitstop-v1`) alongside the new checked board. Earlier full stops use independent `pitstop_sequence_results` / `pitstop_sequence_bests` objects and the device key `spencer_pitstop_results_v2`. The original `pitstop_results` / `pitstop_best_times` and `spencer_pitstop_results_v1` remain readable and unchanged. The two timing formats are never ranked together. Device records work offline and failed uploads retry the same attempt ID.

The earlier online boards rank one best total per case-insensitive crew name and share places for equal totals. The database computes totals from raw milliseconds and penalty count. New full stops must use the v2 format and a raw time of at least 5,100 ms. Public clients can read and append valid stops but cannot update or delete records. Views use invoker security. These remain browser-reported arcade times rather than a verified competitive timing service.

The isolated `pitstop_full_sequence_v2` migration was applied to the existing project. Applied schema references are `supabase/pitstop-sequence-leaderboard.sql` and the earlier `supabase/pitstop-leaderboard.sql`; do not rerun CREATE statements on an already-migrated database. No original pit-stop, Speedway, Holeshot or Rally Cross data, tables or policies were modified. Validation confirmed all 333 existing pit-stop records remained, alongside 480 Speedway, 51 Holeshot and 8 Rally Cross records. Existing project advisors still report pre-existing racing-view findings; the new sequence objects add none. [Supabase advisor guidance](https://supabase.com/docs/guides/database/database-linter?lint=0010_security_definer_view).

Validation: `node pit-stop/tests/core.cjs`; Playwright `node pit-stop/tests/browser.cjs` and `node tools/language-browser.cjs` (Chromium; set `PARTY_BROWSER_PATH` if required). Pit-stop tests cover arrival, both jack actions, every ordered remove/fit cycle, partial holds, safe release, exact optimum timing, early penalties, upload failure and idempotent retry, interruption, original online/device record preservation, English/Spanish labels and responsive controls. The language smoke test covers English defaults, cross-frame Spanish, game screens, option values and Spanish word selection. SQL tests ran as `anon`, verified generated penalties, best-per-name ranking, invalid-input rejection and denied updates, then rolled back all test rows. Live REST reads were checked separately. A hands-on iPhone/iPad session remains to be done.

Pit-stop live labels are written directly in the current language and only when they change. This prevents the animation loop from repainting English between Spanish translation passes. Managed status/result labels also update on language changes. Wheel labels wrap within their controls on smaller screens. The Spanish browser regression intercepts live text writes to ensure English tyre-action labels are never emitted during Mario mode.

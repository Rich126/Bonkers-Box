# Pit Stop Sprint and site languages

Mario mode now uses `spencer_site_language_v2` (`en` by default; `es` only after explicit selection). The old front-page-only preference is ignored during this upgrade. The selected language persists and is shared with same-origin game frames and standalone game pages. Turning Mario mode off restores English.

Every public game page loads the bundled Spanish catalogue and the shared language adapter. Instructions, question/answer copy, creative prompts, game feedback, dialogs, accessible labels and canvas text use that adapter. The Spanish word-guessing game selects Spanish words and includes Ñ in its keyboard. Rendering translations preserve option values, event handlers, game identifiers, player-entered names and stored scores. Game names and livery artwork remain recognisable. There are no runtime calls to a translation service. New English copy should receive a corresponding entry or parameterised pattern in `language-es.js`.

Pit Stop Sprint is available from the Local games menu and at `pit-stop/`. Enter a crew name, wait for green, then hold to loosen, tap to swap and hold to tighten each of four wheels. Each hold takes 450 ms, with one wheel active at a time. Release between actions. On a keyboard, hold keys 1–4; Space releases the car.

The stop clock starts on the shared green-light epoch. Each distinct early work press or car-release press adds three seconds. A car cannot finish until all four tyres are secured. The result shows raw time, penalties and total. Leaving the tab or window during a live attempt cancels it. Device records work without the network; failed uploads can be retried with the same attempt ID.

The independent online leaderboard uses `pitstop_results` and the invoker-security `pitstop_best_times` view. The database computes total time from raw milliseconds and penalty count. It returns one best total per case-insensitive crew name. Equal totals share rank. Public clients may read and append validated stops but cannot update or delete records. Scores are browser-reported arcade times, not a verified competitive timing service.

The isolated `pitstop_leaderboard_v1` migration was applied to the existing Supabase project. Its SQL is retained in `supabase/pitstop-leaderboard.sql` as the applied schema reference; do not rerun it on an already-migrated database. No Speedway, Holeshot or Rally Cross tables, policies or stored times were modified. Before applying it, those result tables held 475, 51 and 7 records respectively. Existing project advisors report pre-existing security-definer racing views; this feature creates an invoker view and adds none of those findings. [Supabase advisor guidance](https://supabase.com/docs/guides/database/database-linter?lint=0010_security_definer_view).

Validation: `node pit-stop/tests/core.cjs`; Playwright `node pit-stop/tests/browser.cjs` and `node tools/language-browser.cjs` (Chromium; set `PARTY_BROWSER_PATH` if required). Tests cover all four tyre changes with actual pointer controls, false-start and unsafe-release penalties, partial holds, upload failure and idempotent retry, interruption, phone layout, English defaults despite the old saved flag, cross-frame Spanish, all standalone game screens, preserved select values and Spanish word selection. SQL tests ran as `anon`, verified generated penalties, best-per-name ranking, invalid-input rejection and denied updates, then rolled back all test rows. Live REST reads were checked separately.
